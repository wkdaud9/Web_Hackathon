# Link-Ton (링크톤) - 해커톤 통합 관리 플랫폼
## 월간 해커톤: 긴급 인수인계 해커톤 제출 기획서

---

## 1. 서비스 개요

### 서비스명
**Link-Ton (링크톤)** - 해커톤의 모든 과정을 연결(Link)하는 통합 플랫폼

### 한줄 소개
해커톤 탐색부터 팀 빌딩, 협업, 제출, 결과 확인까지 모든 과정을 하나의 플랫폼에서 관리할 수 있는 **원스톱 해커톤 매니지먼트 서비스**입니다.

### 개발 목표
- `/data` 폴더에 제공된 명세서와 예시 데이터를 기반으로 **해커톤 통합 관리 플랫폼** 구현
- 필수 요구사항 (7대 섹션, 팀 관리, 제출 시스템) 100% 이행
- localStorage 기반의 독립적인 데이터 아키텍처 구축 (서버 불필요)
- 실제 해커톤 참가자의 니즈를 반영한 **차별화된 확장 기능** 추가

### 타겟 사용자
1. **해커톤 참가자**
   - 개발자, 디자이너, 기획자 등 모든 포지션
   - 팀을 찾거나 팀원을 모집하려는 사용자
   - 해커톤에 처음 참여하는 초보자부터 경력자까지

2. **해커톤 운영진**
   - 참가자 관리, 제출물 수집, 리더보드 관리
   - 투명한 평가 및 순위 공개

3. **해커톤 팀**
   - 프로젝트 협업이 필요한 팀
   - 일정 관리, 아이디어 공유, 리소스 관리

### 제공 가치 (기대 효과)

#### 참가자 관점
- **시간 절약**: 파편화된 플랫폼(공지, 팀 모집, 제출, 협업)을 하나로 통합하여 **탐색 시간 80% 단축**
- **팀 빌딩 효율화**: 통합 팀 모집 라운지로 원하는 포지션의 팀원을 빠르게 매칭
- **협업 편의성**: 별도의 Notion, Slack 없이 팀 워크스페이스에서 아이디어 공유, 일정 관리, 리소스 저장
- **투명성**: 실시간 리더보드로 현재 순위와 경쟁 상황 확인

#### 운영진 관점
- **관리 효율성**: 제출물 수집, 리더보드 업데이트, 팀 현황 파악을 한 곳에서 처리
- **커뮤니케이션 비용 감소**: 중앙화된 알림 시스템으로 공지 전달
- **데이터 투명성**: 모든 활동 내역이 기록되어 분쟁 시 근거 자료로 활용

#### 비즈니스 가치
- **확장 가능성**: localStorage 기반이지만 향후 백엔드(Supabase, Firebase) 전환 시 최소한의 코드 수정으로 대규모 서비스 전환 가능
- **차별화 요소**: 해커톤 플랫폼 + 협업 툴 결합으로 경쟁 서비스 대비 **All-in-One 솔루션** 제공

### 페이지별 상세 구성

#### 📍 1. 메인 페이지 (`/`)
**목적**: 서비스 소개 및 주요 기능으로 빠른 이동

**화면 구성**:
- Hero 섹션: 서비스명, 한줄 소개, 그라디언트 배경
- 3개 갤러리 카드:
  1. **해커톤 탐색**: 진행 중인 해커톤 목록으로 이동
  2. **팀 빌딩**: 팀 모집 라운지로 이동
  3. **명예의 전당**: 랭킹 페이지로 이동

**사용자 행동**:
- 입력: 없음 (읽기 전용)
- 클릭: 각 카드 클릭 시 해당 페이지로 라우팅
- 애니메이션: Framer Motion 스크롤 기반 페이드인 효과

#### 📍 2. 해커톤 목록 페이지 (`/hackathons`)
**목적**: 모든 해커톤을 한눈에 보고 필터링하여 원하는 대회 찾기

**화면 구성**:
- 상단 필터 바:
  - 상태 드롭다운: 전체 / 진행중 / 시작전 / 종료됨
  - 태그 드롭다운: LLM, VibeCoding, Web, AI 등
  - 검색창: 해커톤 제목 검색
- 해커톤 카드 그리드 (반응형: 모바일 1열, 태블릿 2열, 데스크톱 3열):
  - 썸네일 이미지
  - 제목, 상태 배지, 태그
  - 일정 (제출 마감일, 종료일)
  - 참여 팀 수
  - "자세히 보기" 버튼

**사용자 행동**:
- **입력**: 필터 선택, 검색어 입력 (300ms 디바운스)
- **동작**: 실시간 필터링 (AND 조건)
- **결과**: 조건에 맞는 해커톤만 표시, 조건 없으면 전체 표시
- **클릭**: 카드 클릭 시 해커톤 상세 페이지로 이동

**예외 처리**:
- 로딩 중: LoadingSpinner 표시
- 데이터 없음: EmptyState (아이콘 + "해커톤이 없습니다" + "메인으로" 버튼)
- 필터 결과 0건: "검색 결과가 없습니다" 메시지

#### 📍 3. 해커톤 상세 페이지 (`/hackathons/:slug`) ⭐ **핵심 페이지**
**목적**: 한 해커톤의 모든 정보를 7개 섹션으로 구조화하여 제공

**화면 구성**: 탭 네비게이션 (스티키 헤더) + 스크롤 연동

##### 📌 섹션 1: Overview (개요)
- **내용**: 해커톤 소개, 팀 구성 정책, 유의사항
- **표시**: 마크다운 형식의 텍스트
- **행동**: 읽기 전용

##### 📌 섹션 2: Info (일정/상금)
- **내용**:
  - 타임라인: 마일스톤 목록 (접수, 개발, 제출, 심사, 결과 발표)
  - 시상 내역: 1위~3위 상금 (KRW)
  - 중요 링크: 규칙, FAQ 외부 링크
- **표시**: 테이블 형식
- **행동**: 외부 링크 클릭 시 새 탭에서 열기

##### 📌 섹션 3: Evaluation (평가기준)
- **내용**: 평가 메트릭 (정확도, F1-Score 등), 설명, 제한사항
- **표시**: 카드 형태
- **행동**: 읽기 전용

##### 📌 섹션 4: Teams (팀 목록)
- **내용**: 이 해커톤에 참여 중인 모든 팀 카드
- **카드 구성**: 팀명, 팀코드, 멤버 수, 리더 정보, "상세보기" 버튼
- **사용자 행동**:
  1. **팀 상세 보기**: 모달 팝업 (팀 소개, 멤버 목록, 연락처)
  2. **팀 가입 신청**: "가입 신청" 버튼 클릭 → 팀 리더에게 알림 전송
  3. **팀원 초대** (리더 전용): 랭킹 페이지나 검색에서 사용자 선택 → 초대 전송

**팀 초대/신청 플로우**:
```
[시나리오 A: 리더가 유저 초대]
리더: 랭킹 페이지에서 "팀원 초대" 버튼 클릭
  → 초대 데이터 생성 (type: 'invite', status: 'pending')
  → 피초대자 알림 FAB에 배지 표시
피초대자: 알림 FAB 클릭 → "수락/거절" 버튼
  → 수락 시: 팀 멤버 추가, 초대 제거, 토스트 알림
  → 거절 시: 초대만 제거

[시나리오 B: 유저가 팀 가입 신청]
유저: 팀 상세 모달에서 "가입 신청" 버튼
  → 신청 데이터 생성 (type: 'application', status: 'pending')
  → 팀 리더 알림 FAB에 배지 표시
리더: 알림 FAB 클릭 → "수락/거절" 버튼
  → 수락 시: 신청자를 팀 멤버에 추가
  → 거절 시: 신청만 제거
```

##### 📌 섹션 5: Submit (제출)
- **내용**: 결과물 제출 양식
- **입력 필드**:
  - 제출 타입 선택: 개인 / 팀 (라디오 버튼)
  - 팀 선택: 드롭다운 (내가 속한 팀 목록)
  - 메모: textarea (선택사항)
  - GitHub 링크: input (선택사항)
  - 파일 업로드: file input (선택사항, zip/pdf)
    - **참고**: 실제 파일 업로드는 시뮬레이션 (파일명만 저장)

**사용자 행동**:
- **입력**: 위 필드 작성
- **동작**: "제출하기" 버튼 클릭
- **결과**:
  - 검증: 필수 필드 (제출 타입, 팀명) 체크
  - 성공: localStorage에 submission 추가, 토스트 "제출 완료!", 리더보드 갱신
  - 실패: 에러 토스트 표시
- **추가 기능**:
  - 이미 제출한 경우: "수정하기" / "삭제하기" 버튼 표시
  - 수정: 기존 데이터 불러와 폼 채우기 → 재제출
  - 삭제: 확인 모달 → 삭제 후 토스트

##### 📌 섹션 6: Leaderboard (리더보드)
- **내용**: 실시간 순위표
- **표시**:
  - 순위, 팀명, 점수, 제출 시간
  - 미제출 팀: "미제출" 표시 (순위 없음)
  - TOP 3: 금/은/동 아이콘 강조
- **정렬**: 점수 내림차순 (점수 같으면 제출 시간 빠른 순)
- **사용자 행동**: 읽기 전용, 자동 갱신 (제출 시)

**예외 처리**:
- 해커톤 데이터 없음: ErrorState ("해커톤을 찾을 수 없습니다")
- 로딩 중: 각 섹션 스켈레톤 로딩

#### 📍 4. 팀 모집 라운지 (`/camp`)
**목적**: 해커톤별 팀 모집 공고 등록 및 검색

**화면 구성**:
- 상단:
  - "팀 만들기" 버튼 (모달 팝업)
  - 필터 바: 해커톤 선택, 모집 상태 (전체/모집중/마감), 검색
- 팀 카드 리스트:
  - 팀명, 해커톤, 멤버 수, 모집 포지션 태그
  - 모집 상태 배지 (열림/마감)
  - 팀 소개 미리보기
  - "상세보기" 버튼

**팀 만들기 모달**:
- **입력**:
  - 해커톤 선택: 드롭다운
  - 팀명: input (필수)
  - 팀 소개: textarea (필수)
  - 모집 포지션: 다중 선택 체크박스 (Frontend, Backend, Designer, PM 등)
  - 연락처: input (오픈카톡/구글폼 URL)
- **동작**: "팀 생성" 버튼 클릭
- **결과**:
  - 검증: 필수 필드 체크
  - 성공: teams에 추가, currentUser를 리더로 설정, 토스트 "팀 생성 완료!"
  - 실패: 에러 토스트

**사용자 행동**:
- **필터링**: 실시간 필터 적용
- **팀 상세 보기**: 모달 팝업 (멤버, 소개, 연락처 표시)
- **가입 신청**: 팀 상세 모달에서 "가입 신청" 버튼

**예외 처리**:
- 로그인 안 됨: "팀 만들기" 버튼 → 로그인 모달 팝업
- 데이터 없음: "등록된 팀이 없습니다"

#### 📍 5. 랭킹 페이지 (`/rankings`)
**목적**: 전체 사용자 활동 점수 기반 명예의 전당

**화면 구성**:
- 상단:
  - 기간 필터: 전체 / 최근 30일 / 최근 7일 (탭)
  - 검색창: 닉네임 검색
- TOP 3 강조 표시:
  - 1위: 금메달 + 큰 카드
  - 2위: 은메달 + 중간 카드
  - 3위: 동메달 + 중간 카드
- 4위 이하: 테이블 형식
  - 순위, 프로필 이미지, 닉네임, 포인트
  - 액션 버튼: "프로필 보기", "팀원 초대", "메시지"

**사용자 행동**:
- **프로필 보기**: 모달 팝업
  - 공개 프로필: 닉네임, 포인트, 레벨, 참여 해커톤 수
  - 비공개 프로필: "비공개 프로필입니다" 메시지
- **팀원 초대**: 드롭다운에서 내 팀 선택 → 초대 전송
- **메시지**: DM 채팅 모달 팝업

**정렬**:
- 기본: 포인트 내림차순
- 검색 결과: 일치도 우선 + 포인트

**예외 처리**:
- 사용자 없음: "등록된 사용자가 없습니다"
- 검색 결과 없음: "검색 결과가 없습니다"

#### 📍 6. 마이페이지 (`/mypage`)
**목적**: 개인 프로필 및 활동 내역 관리

**화면 구성**: 4개 섹션

##### 섹션 1: 프로필
- **표시**: 프로필 이미지, 닉네임, 레벨, 포인트
- **입력**: "닉네임 변경" 버튼 → 인라인 input 표시 → "저장"
- **토글**: 프로필 공개/비공개 스위치
- **동작**: 변경 시 localStorage의 currentUser 업데이트

##### 섹션 2: 내 팀
- **표시**:
  - 내가 리더인 팀 (리더 배지)
  - 내가 멤버인 팀
- **카드**: 팀명, 해커톤, 멤버 수
- **버튼**: "워크스페이스로" (팀 워크스페이스 페이지로 이동)

##### 섹션 3: 참여 내역
- **표시**: 내가 참여한 해커톤 목록
- **카드**: 해커톤 제목, 상태, 팀명

### 4.4 리더보드 시스템

#### 순위 계산 로직
```typescript
function calculateLeaderboard(hackathonSlug: string): LeaderboardEntry[] {
  const submissions = getSubmissions(hackathonSlug);
  
  // 1. 제출한 팀만 점수 부여
  const entries = submissions.map(sub => ({
    rank: 0,  // 임시
    teamName: sub.teamName,
    score: calculateScore(sub),  // 평가 로직 (실제로는 심사위원 점수)
    submittedAt: sub.submittedAt
  }));
  
  // 2. 점수 내림차순 정렬
  entries.sort((a, b) => {
    if (b.score !== a.score) return b.score - a.score;
    // 점수 같으면 제출 시간 빠른 순
    return new Date(a.submittedAt).getTime() - new Date(b.submittedAt).getTime();
  });
  
  // 3. 순위 부여
  entries.forEach((entry, idx) => entry.rank = idx + 1);
  
  return entries;
}
```

#### 실시간 갱신
- **트리거**: 제출 시, 제출물 수정/삭제 시
- **동작**:
  1. calculateLeaderboard() 호출
  2. leaderboards 배열 업데이트
  3. storage-update 이벤트 발행
  4. Leaderboard 섹션 자동 리렌더링
- **결과**: 페이지 새로고침 없이 순위 즉시 반영
