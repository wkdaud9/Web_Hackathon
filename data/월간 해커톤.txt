[공지] 월간 해커톤 : 긴급 인수인계 해커톤 - 문서만 남기고 사라졌다

개발자가 남긴 자료와 단서를 조사하고 vide coding으로 미션을 완료하라!

- 대회 소개
	- 웹페이지 형태의 서비스를 개발해야 합니다.
	- 하지만, 기능은 아직 미완성이고 초보 개발자는 어디서부터 구현해야할지 막막한 상황입니다.
	- 이번 해커톤에서는 바이브 코딩을 활용해 제공된 자료를 기반으로 웹페이지를 완성하고 팀만의 아이디어로 확장해 더 좋은 서비스 경험을 제안해 주세요.

- 목표
	- 제공된 자료(Data 폴더)를 기반으로 웹페이지를 완성
	- 자료를 바탕으로 팀의 아이디어로 확장 기능/UX 개선을 목표로 함
- 기술 환경
	- 개발 도구 : 기술 제한 없이 바이브 코딩 툴을 활용하여 개발
	- 배포 : Vercel 배포 필수
- 평가 기준
	1차 평가 : 최종 제출한 참가팀 및 심사위원 상호 투표평가
	참가팀 가중치 : 30%, 심사위원 가중치 : 70%
	1차 투표평가 상위 10팀에 대해 내부 심사위원 정성평가(100%) 진행

- 내부 심사위원 평가기준

	- 기본 구현 : 웹 페이지 구현도, 데이터 기반 렌더링, 필터/정렬 동작, 빈 상태 UI
	
	- 확장(아이디어) : 팀 고유 기능/UX 개선의 참신함·실용성, “서비스로서 가치”가 드러나는 확장, 일관된 흐름

	- 완성도 : 사용성(동선/가독성), 안정성(오류/예외 처리), 성능(로딩/반응성), 접근성/반응형

	- 문서/설명 : 기획서의 명확성, PPT의 설계/구현 설명력, 실행/검증 방법(재현성)

※ 동점자 처리 기준

심사위원 득표수가 많은 팀이 우선순위

팀에게 부여된 투표권 중 사용하지 않은 투표수가 적을수록 우선순위

산출물 최초 업로드 시간이 빠를수록 우선순위

규칙
제출물

기획서(1차 제출) : 서비스 개요,페이지 구성, 시스템 구성, 핵심 기능 명세, 주요 사용 흐름, 개발 및 개선 계획

웹 페이지

Vercel 배포 URL(필수)

Github 저장소 링크(필수)

솔루션 설명 자료(PDF)

PPT로 제작 후, PDF로 변환하여 제출

분량 및 디자인의 제한 없음

개발/배포 규칙

배포 URL은 외부에서 접속 가능해야하며 심사 기간동안 접근 가능해야합니다.

기술 선택은 자유입니다.

예시 자료 외 데이터는 제공되지 않습니다.

더미 데이터/로컬 저장소(localStorage 등)를 활용해 구현하세요.

필요한 정보는 팀이 더미 데이터로 구성하고, 변경 사항은 로컬에 저장되어 유지되도록 구현하면 됩니다.

외부 API/외부 DB를 쓰는 경우에도 심사자가 별도 키 없이 확인 가능해야 합니다.

(키가 필요한 기능은 평가에서 확인이 제한될 수 있음)

공정성/저작권
제출물(코드/이미지/폰트/아이콘 등)은 저작권·라이선스를 준수해야 합니다.

타인의 결과물을 무단 복제/도용하거나 라이선스를 위반한 경우 실격 또는 감점될 수 있습니다.

팀 내 역할/분업은 자유이며 생성형 AI 도구 사용은 허용합니다.

심사 관련 유의사항
심사는 기본적으로 배포 URL을 기준으로 진행합니다.

확인이 어려운 기능은 심사에서 제외될 수 있습니다.

운영진의 추가 안내가 있을 경우 공지 내용이 우선 적용됩니다.
